# Surface weathering — November 27, 2026

Surface weathering extends the existing LotPathBlend and StreetJunction surface passes. Road meshes, cross sections, UV0, base PBR textures, physical heights and draw counts are unchanged. Natural soft dirt sidewalks retain their previous treatment; paved/wood sidewalks have a separate profile. No decals or overlay meshes are created.

## Inspector controls

Select `Assets/CityForge/Resources/SurfaceWeathering/Road.asset` or `Sidewalk.asset` in Unity's Project panel. These shared ScriptableObjects expose master intensity, gutter width **in metres**, gutter darkness, grime strength/repeat in metres, sediment strength/tint/repeat, sparse organic debris strength/repeat, camber, moisture variation, contact shading and sidewalk edge weathering. Edit while playing; changes propagate on the next LateUpdate without rebuilding roads or restarting Play.

Updated reference-tuned defaults: road master 0.90 / grime 0.06; sidewalk master 0.70 / grime 0.07714286, both giving effective broad grime 0.054. Road gutter width 0.70m, darkness 0.25, sediment 0.60; sidewalk width 0.45m, darkness 0.25, sediment 0.28. Debris strength road 1.0 / sidewalk 0.85 with 9.5m source repeat, tint (1.7,1.5,1.1), offset scatter 0.70. Edge breakup 0.95 with 12m patch repeat. Contact 0.26, sidewalk edge shading 0.25, moisture 0.08; camber remains OFF. All strengths are additionally multiplied by master intensity. Optional camber is a world-normal perturbation; it never raises or moves vertices and preserves the authored tangent normal map.

`Resources/SurfaceWeathering/Library.asset` stores persistent default profiles and material/era overrides. Edit this asset for assignments that must survive between sessions; changes propagate live through the same revision mechanism. The component overrides below apply after the shared library.

`SurfaceWeatheringSettings` is attached to the active PrototypeRegionView when roads are presented. Its Road Profile and Sidewalk Profile fields are independent. The Overrides list matches LotPathMaterial IDs and EraAppearance IDs; blank ID fields match all. Last matching entry wins. An override with a null profile disables weathering for that match. Create additional profiles through Assets → Create → CityForge → Surface Weathering Profile, and assign the shared texture references. Profile choices are presentation configuration, not new road/save metadata. Runtime-only changes to the settings component are session scoped; shared profile asset settings persist in the Editor.

Master zero disables the weathering keyword, texture samples and all weathering math. Existing road/junction shading remains. A sidewalk that originally used URP Lit switches back to its original shader at zero, then back to the weathering shader when re-enabled. Existing base texture mapping and normal/metallic/specular/occlusion/emission properties are retained.

## Coordinates and connections

Existing UV1 contains distance across the ribbon in metres (x), width (y), distance along (z), and signed open/closed length (w). Normalized cross-road coordinate is x/y; no new mesh attribute is written. Ordinary standalone ribbons use min(x,y-x). District roads and sidewalks reuse the native signed RoadRecess field built from StreetSurfaceMask.BoundaryEdges of the combined road footprint. Internal connected edges are absent, so gutter/contact accumulation follows exterior boundaries through curves, X/T junctions and rounded connections. Sidewalk shading uses absolute distance on the outside of the same field rather than shading its arbitrary clipped triangle edges.

The existing recess field is capped at 1024², has a 2m distance range and bilinear sampling. Gutter width is limited to 0.05–1.5m. The field remains the existing system: on very large or widely separated road footprints its texels may become wider than a narrow gutter. This is a pre-existing field resolution limit, not an exact analytic boundary representation. A tiled higher-resolution boundary field would be a separate future optimization; no road-generation rewrite is included here.

World XZ sampling shares texture phase across segments. Grime uses two samples (one rotated and at a broader scale) to break the obvious repeat. Sediment and RGBA debris use one sample each. Sparse supplied debris alpha controls coverage. Sediment and darkening accumulate in irregular gutter pockets; leaves use a slightly wider falloff for scattered strays. Native paved sidewalks also receive a subtle outer dirt/shading band at their physical 1m grass-facing edge, derived from the same road boundary rather than clipped mesh triangles. Moisture makes only a small change to the original smoothness. Road shading reuses the boundary distance already evaluated by the recess pass; sidewalks need one field lookup. Parameter-disabled effect groups skip their texture samples. No parallax or simulation was added; pre-existing material displacement remains as authored.

## Assets and batching

The three 1024² supplied PNGs are installed once in `Resources/SurfaceWeathering/Textures`. All PNG bytes are unchanged. Grime is linear; sediment/debris are sRGB; debris input alpha is retained; all use Repeat, mipmaps and trilinear filtering. PNGs remain Git-ignored/private. Source-controlled import metadata preserves their GUIDs and settings; the profiles refer to those GUIDs. A source-only checkout still needs the supplied PNGs copied into that folder. Missing color textures suppress the corresponding blend rather than painting placeholder colors.

Both modified shaders use a single invariant UnityPerMaterial buffer and have GPU instancing variants. Native ShaderUtil checks report SRP-batcher compatibility code 0 for both. Existing material property blocks (e.g. dirt-junction arrays) retain their previous batching constraints. Shared runtime materials remain shared; no per-road weathering material clones or property blocks are created.

`PathMaterialInput.hlsl` loads URP LitInput dependencies before extending its single material buffer at CBUFFER_END. It reuses the installed URP implementation without copying or editing package source. The macro is immediately restored. This is validated against the project's pinned Unity 6000.1.12f1 / URP 17 layout; recheck the buffer extension and compatibility checks when upgrading URP.
